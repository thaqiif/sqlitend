DDestroy & cleanupthe delete path under load & after

Every database was deleted through the API, then the workspaces were removed. The control plane killed each sqld process, freed its port, removed its data directory and its per-database signing key, and cleaned now-empty parents — a gap found during this test and fixed in the same session.

MMethod & honesty

How it ran

Three workers: two writers (10 databases each, batched 250-row multi-value inserts via @libsql/client over Hrana WebSocket) and one reader/verifier. Every insert batch verified with an exact COUNT(*). A 3-second host sampler recorded memory, process count, port latency, and database count throughout. The whole run fitted comfortably — ~580 MB was still free at the hottest instant, with no swap.

Caveats

This is a single-node, single-CPU test on deliberately small hardware — a production box is bigger. Latencies include a Tailscale link, not pure loopback. The control plane has no login in v1: put it behind a firewall or authenticated reverse proxy on a real network. Database tokens are per-database and full-access; data access itself stayed isolated — a token for one database was rejected by every other (verified in this run).
